Blocking errors — with a fix, not a lecture

That's an IPv6 address — an A record holds IPv4.
A CNAME can't sit at the apex — it would collide with the zone's own SOA and NS records.
www already has an A record. A CNAME can't coexist with another record at the same name.
Collision checks run against the already-loaded zone — no extra request. The backend enforces structure (zone containment, apex NS/SOA, label charset) but never checks that an A holds IPv4 or that a CNAME is unique at its name; those gaps are what this layer closes. The server stays the authority and its rejections are shown verbatim.

Key material

Serving hosts pull certificate material themselves over the job channel after a certificate_updated broadcast, using their own API key. It is not downloadable from this panel.

No download-material control, at any permission level (D6). GET certificate/material/<pk> exists for serving hosts, is gated on manage_dns plus a superuser check for house certificates, and logs every release. The UI states the sync model in a sentence instead of offering a private key over the browser.
Expiry tone. certExpiryTone() — danger under 14 days, warning under 30, success otherwise, secondary when days_remaining is null (no not_after yet). One tested helper, never an inline ternary.
Auto-refresh is conditional. The issuing row above is why: autoRefresh runs only while a non-terminal (pending/issuing) row is present, with an idempotent start and a self-terminating tick — cached-page unmount() does not fire child onBeforeUnmount (WM-034).
Revoke, not delete. CAN_DELETE=False; the kebab offers Revoke (danger, manage_dns) only when status === 'active'.

A typed TLD never collapses the grid. nativemojo.com and nativemojo return the same three sections — the full name just pins an exact-match row on top. Answering a full-name search with one "already registered" row is the dead end this feature exists to remove: .com is the likeliest name to be taken, so the alternatives must be on screen at the moment the bad news is. The exact name resolves first and renders as soon as it lands, so a precise check is never slower than a single-name search.
Data source is capability-detected (D10). With django-mojo item 412: one batch registrar/search for the TLD grid and one registrar/suggest for the similar-names block, with per-TLD pricing served from the backend cache. Without it: client fan-out over a 5-TLD default at concurrency 3, rows filling in as they resolve, and the similar-names block omitted entirely — AWS GetDomainSuggestions has no client-side equivalent.
Why not just fan out from the browser? check_availability() makes two AWS calls per name — check_domain_availability plus an uncached list_prices(tld). An 8-row grid is 16 AWS calls, half of them re-fetching static pricing. And CheckDomainAvailability is the call that degrades to PENDING under load, so fanning out manufactures more of the null state than it resolves.
A row that errors, times out or is throttled is unknown — never taken. Partial results render as they land rather than blocking on the slowest row.
