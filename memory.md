## Key Decisions
- **Model+View pattern** — the primary record on a view is always `this.model`; JS reads via `this.model.get('field')`; templates read via `{{model.field}}`; child views receive `model: this.model`.
- **REST API — standard CRUD, no admin endpoints** — the permission system (User → Group → Member) handles access control per Model. All API access uses the same CRUD endpoints; admins filter with query params (e.g., `/api/account/api_keys?user=123`). Never create or assume separate admin-scoped endpoints like `/api/user/{id}/resource`.
- **Agent boot path** — `CLAUDE.md` → `memory.md` → `scripts/board.sh`, then `/scope` (triage+intake) or `/build` (implement). Work items live in `planning/{inbox,confirmed,done}/`; ids come from `scripts/intake.sh`.
- **Docs source of truth** — local `docs/web-mojo/` is authoritative when inside this repo; never rely on `docs/pending_update/`.
- **Consumer agent file** — `docs/web-mojo/AGENT.md` is a drop-in for downstream projects and is intentionally separate from the internal `AGENT.md`.
- **Contributor guide** — `DEV_GUIDE.md` is contributor-facing and not part of the default agent boot path.
- **Chrome UI testing** — use `find` + `computer left_click` (real mouse clicks) for UI interaction testing. Never use `.click()` via `javascript_tool` — it bypasses the event pipeline and causes 404s on `<a>` tags. Use `javascript_tool` only for DOM assertions. Full protocol in `prompts/testing.md`.
- **View modules: trailing `export default X;`, not inline** — the test harness's `SimpleModuleLoader` only transforms a trailing `export default Name;` (like `DetailView`/`JobDetailsView`); an inline `export default class X extends View {…}` loads as `undefined`, so unit tests can't `Object.create(Cls.prototype)`. Use the trailing form for any view you want behavioral (non-source-text) tests on. (ITEM-015)
- **UI permission gating: `View#checkPermissions`, fail-closed** — `permissions:` keys on toolbar buttons and TableRow context-menu items gate through `View#checkPermissions` → `getApp()?.activeUser?.hasPermission()` (any-of for arrays); no resolvable user ⇒ hidden. Row menu items also support `visible(model)` (throwing predicate = hidden + warn) and callback `action(model, app)` (dispatched by original index via `data-menu-index`); `rowContextMenu` is an alias for `contextMenu` on TableView/TablePage. Escape any dev-supplied string flowing into template HTML with `escapeHtml` — and `escapeHtml` implementations must be explicit-replace (quote-safe), NOT div.textContent/innerHTML, because they're used in attribute contexts. (ITEM-020)
- **`admin` permission semantics** — User-record `admin` is the system-wide full-access wildcard (superuser-equivalent; name-checked in `hasPermission()`, deliberately **not** in `CATEGORY_GRANULAR_MAP`); surfaced as **"System Admin"** leading `User.CATEGORY_PERMISSIONS`. Member-record `admin` (**"Group Admin"**, leads `Member.BASE_PERMISSIONS`) is full access within that group only, never `sys.*`. `manage_group` (**"Manage Group"**) is a literal group-management perm, not an admin grant. Three distinct things: `admin` (system), member `admin` (group), `view_admin` (admin-panel entry). (ITEM-019)
- **`skipRender` model-change option** — `model.set(data, null, { skipRender: true })` / `model.save(data, { skipRender: true })` emit `change` normally but suppress the automatic `View` rerender (options are forwarded to listeners: `emit('change', model, options)`). FormView inline autosave uses it so saving one field doesn't rebuild parent views (was resetting tab state). Any view that hand-rolls its own `model.on('change', …)` rerender listener (e.g. DataView) must check the flag itself. (ITEM-016)
- **`epoch` formatter is format-agnostic** — the backend toggles timestamp serialization between epoch seconds and ISO-8601 strings, so `epoch` (DataFormatter) only `×1000`s *entirely-numeric* values; ISO/date strings, `Date` instances, and null/undefined/'' pass through unchanged for the downstream date formatter (`normalizeEpoch()` parses ISO via `Date.parse`). **Keep piping `epoch|datetime` / `epoch|relative` everywhere — never strip `epoch|` to "fix" an ISO field; fix belongs in the formatter.** Was `parseFloat('2026-…')`→2026→garbage date. (ITEM-021)
- **Page lifecycle traps** — (a) a Page `onEnter` override MUST `await super.onEnter()` (base sets `isActive`/clears `_wasExited`; skipping it makes `render()` a no-op on every revisit → blank page); (b) never `await` a fetch in `onEnter` — `WebApp.showPage` renders only after `onEnter` returns, so the page stays blank until the API answers; fire-and-forget + apply when children exist (stash + `onAfterMount` on first visit). (ITEM-023)
- **Pipes on empty arrays were broken framework-wide (fixed 2026-07-08)** — `dataFormatter.apply()`'s alternate-shape detection (`apply(value, [...pipeNames])`) misfired on `[]` (vacuous `every()`), returning the formatter NAME string (truthy) for ANY pipe on an empty array — flipping both `{{#x|bool}}` and `{{^x|bool}}`. Fixed with a non-empty guard + regression tests (`test/unit/Mustache-piped-sections.test.js`); both piped section forms now match Templates.md. Also: FormBuilder `json` fields return a parsed OBJECT from `getFormData()` when content is valid JSON (string when invalid) — coerce both (`geofenceData.coerceRuleInput`). (ITEM-023)
- **App-wide upload ceiling: `max_upload_size` (bytes, snake_case) in WebApp config** — resolved by `FileDropMixin.resolveMaxUploadSize(explicit, fallback)`: first positive finite number of page `maxFileSize` option → `app.config.max_upload_size` → surface fallback (storage Files page: 1 GB; 10 MB mixin baseline if every candidate is invalid). Storage-page-only by scoped decision — ChatInputView / FormView image fields / ImageUploadView stay at 10 MB. App-config keys follow the `shortlink_base_url` snake_case precedent. Loader gotcha: the test harness's `export default` transform also mangles COMMENTS containing that token pair — keep the phrase out of comments in harness-loadable modules. (ITEM-024)
- **Group `metadata` writes are deep-merged (objict.merge_dicts)** — `null` DELETES a key, lists overwrite, nested `__replace` is NOT supported (it would be stored + fail validation). To "replace" a nested config object (e.g. `metadata.geofence`), send a null-diff: new values + explicit `null` for every removed key/operator (`geofenceData.buildGroupRulePayload`). (ITEM-023)

- **ApiKey permissions = Member catalog, dotted-key switches (ITEM-025)** — an API key "acts as" a group member: its permissions editor offers exactly `Member.PERMISSION_TABSET`, embedded LIVE via a `fields` **getter** in `ApiKeyForms.create` (`rebuildPermissions()` replaces the tabset element in place, so a module-load spread captures a stale object). Saves are flat dotted `permissions.<name>` booleans (django-mojo expands pre-gate, per-key `can_change_permission`); creates are grant-only — strip falsy `permissions.*` keys before POST. Modal-layout trap: `noBodyPadding: true` + `buttons: []` are valid ONLY for `DetailView` bodies (they bring their own padding + × close); on a hand-rolled `View` those options remove all padding and every dismiss control — exactly how the old ApiKeyView modal looked broken. `is_active` belongs on the DetailView header active switch, not in edit forms. (ITEM-025)

## Lint Baseline
- `npm run lint` = `eslint src` (fixed 2026-07-08; the old `src/**/*.js` glob never recursed under /bin/sh — extensions were NEVER linted). Baseline: **0 errors / 316 warnings**. Warnings are tracked debt: 4 recommended rules downgraded to warn (`no-useless-escape`, `no-case-declarations`, `no-prototype-builtins`, `no-empty`); intentional lazy `import()` sites carry inline eslint-disable comments; `bootstrap` is a declared global; generated `countryCentroids.js` is ignored (its BQ/ES/TF duplicate keys are a generator artifact).
- **Unit-testing a heavy DetailView-based view — loader import mechanics (ITEM-026)** — `simple-module-loader` transforms imports at load: a **default** import whose path maps in `importPathToGlobal` → `const X = global.X` (captured at load, so set the global BEFORE `loadModule`; you may then `delete` it — the module keeps its captured ref); an **unmapped default** import → a constructible module-local stub; but an **unmapped named** import (`import { LogList }`) → `const X = undefined`, so a constructor-time `new X()` throws. A view that `new`s a model/collection in its constructor therefore needs that model's path in `importPathToGlobal` (added `models/Log.js → LogList`) and the view registered in the loader. Never leave a `global.<RealModule>` assigned — it leaks into later test files (once broke a `ShortLinkView` `instanceof MetricCard` assertion via loadModule's cache-hit not restoring the global); capture-then-`delete`, or don't touch it. Prefer construction-only assertions (read `headerConfig`/`sectionsConfig`, drive action handlers directly) over full `render()`.
